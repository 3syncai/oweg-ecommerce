## Implementation decisions

- Vendor selection requires the exact public SKU, quantity, and customer price. There is no silent colour, size, or price substitution.
- When all candidates have verified coordinates, rank by Haversine distance between postal centroids. Distances within 5 km are treated as tied and resolved with a cryptographic random draw. If coordinates are incomplete, vendors with the same PIN as delivery are preferred; otherwise draw randomly among eligible candidates. This avoids pretending an unverified coordinate is accurate.
- Initial selection candidates and reason are stored in order metadata. Medusa order edits hold the assignment history. The vendor earnings ledger holds each financial debit.
- Seller inventory variants retain unique `OWEG-OFFER-…` identifiers internally. New order line snapshots and reassigned items use the mapped public catalog SKU so admin and fulfillment views show a readable SKU. Order #1182 was corrected to `PRL-TEE-BLK-M-01`.
- Admin can explicitly choose a previously assigned seller again when the same SKU, price, stock, and acceptance rules allow it. Automatic reassignment still excludes earlier sellers to avoid loops.
- An admin-cancelled vendor assignment remains visible as a cancelled item with the admin reason in that vendor's Orders view. Its cancellation debit is shown in Payments with the customer order number; order #1182 booked ₹20 plus ₹3.60 GST against TEST, labelled `CANCEL-1182`.
- The first vendor's configured cancellation fee and GST apply when their assignment moves. No payment gateway fee applies because the customer order remains open. A whole order cancellation charges the current vendor's configured cancellation fee plus the prepaid gateway fee; COD has no cancellation gateway fee.
- Replacement choices expire after `VENDOR_REPLACEMENT_RESPONSE_HOURS`, default 48 hours, bounded to 1–168 hours. Expiry leaves the customer order open for admin resolution.
- An admin may record a phone, WhatsApp, email, or in-person decision with specific consent evidence. Assisted acceptance requires a customer code bound to one offered variant and price; the customer receives a confirmation email. The customer's authenticated order page remains an alternative.

## Manual QA

- Place two orders for the same variant/price with sellers at different verified distances, and inspect the assignment metadata. Repeat with locations within 5 km to confirm both can win.
- Confirm an out-of-stock colour or size blocks checkout and a different variant appears only as an approval choice.
- Accept one order before the deadline; simulate an overdue order and confirm server rejection, admin alert, and replacement deadline reset.
- Reassign A to B; verify A has one cancellation debit and B sees the updated order. Cancel a subsequent order and verify only its current vendor receives the full cancellation charges.
- Offer a higher-priced or different-sized replacement; reject, expire, approve in the customer account, and record an assisted admin decision. Verify that edits wait for consent and payment/refund settlement, and the customer receives confirmation of an assisted decision.
- For assisted acceptance, send a code for variant A, verify that it cannot approve variant B, enter an incorrect code five times, request a fresh code, and verify that an expired code cannot approve. Confirm that the customer email names the exact attributes and price.
